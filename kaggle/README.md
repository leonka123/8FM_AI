# Обучение «абсолютной» модели на Kaggle

Здесь лежит всё, чтобы обучить максимальную Classic-политику проекта
(`lu_luna_absolute`) на внешних мощностях, а не на ноутбуке.

```
kaggle/
├── 8fm-absolute-training.ipynb   # готовый ноутбук: клонирует репо и запускает обучение
├── train_absolute.py             # возобновляемый драйвер обучения (можно запускать где угодно)
└── README.md                     # этот файл
```

## Почему Kaggle и почему без GPU

Симулятор и сеть написаны на чистом Python + NumPy. GPU тут не поможет —
узкое место это поштучный проигрыш игр в Python. Полезны только **ядра CPU**:
драйвер запускает несколько игр параллельно в процессах (`--workers 4`), что
даёт примерно 3–4-кратное ускорение на 4 vCPU Kaggle.

Каждая сессия Kaggle — примерно 12 часов, 30 часов в неделю. Полный прогон
не влезает в одну сессию, поэтому драйвер учит **чанками** и продолжает
в новой сессии с того же шага.

## Быстрый путь (ноутбук)

1. Откройте [kaggle.com](https://www.kaggle.com) → **Create → New Notebook**.
2. **File → Import Notebook** → загрузите `8fm-absolute-training.ipynb`.
3. В панели **Settings** справа:
   - **Internet: On** (иначе `git clone` не пройдёт);
   - **Accelerator: None** (GPU не нужен).
4. **Save Version → Save & Run All (Commit)**.
5. Когда сессия закончится, загляните в **Output**: заберите
   `lu_luna_absolute.json` (лучшая модель) и `lu_luna_absolute-metrics.json`.
6. Чтобы продолжить — запустите ноутбук снова: он возобновит обучение.

## Ручной путь (терминал, любой Linux)

```bash
git clone https://github.com/leonka123/8FM_AI
cd 8FM_AI

# один прогон: чанк за чанком, пока не кончится бюджет времени
python kaggle/train_absolute.py \
    --work-dir /kaggle/working \
    --workers 4 \
    --total-updates 6000 \
    --chunk-updates 200 \
    --games-per-update 48 \
    --warm-start-games 6000 \
    --time-budget-seconds 30000
```

Если сессия прервалась — просто запустите команду ещё раз. Драйвер сам
прочитает `driver_state.json` и продолжит с того же глобального шага.

### Полезные флаги

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--work-dir` | где лежат чекпоинты и состояние | `/kaggle/working` |
| `--total-updates` | сколько всего апдейтов обучать | `6000` |
| `--chunk-updates` | размер одного чанка между сохранениями | `200` |
| `--games-per-update` | игр на апдейт | `48` |
| `--workers` | параллельных процессов сбора игр | `4` |
| `--warm-start-games` | игр для behaviour cloning при старте с нуля | `6000` |
| `--time-budget-seconds` | остановиться до лимита сессии (`0` = без лимита) | `30000` |
| `--min-chunk-seconds` | не начинать чанк, если осталось меньше | `600` |
| `--reset` | забыть прошлое состояние и начать заново | выкл. |

## Что получается на выходе

В `--work-dir` появятся:

- `lu_luna_absolute.json` — **лучшая** модель по композитному скору
  (её и переносите в проект);
- `lu_luna_absolute-latest.json` — последняя сеть (нужна только для
  продолжения обучения);
- `lu_luna_absolute-metrics.json` — метрики по всем чанкам и сессиям
  (можно рисовать графики);
- `driver_state.json` — служебный файл с глобальным шагом и лучшим скором;
- `checkpoints/` — архив снимков каждые `--checkpoint-every` обновлений.

## Перенос модели на ноутбук

1. Скачайте `lu_luna_absolute.json` из **Output** (или скопируйте с
   `--work-dir`).
2. Положите в локальный проект, например в `models/lu_luna_absolute.json`.
3. Пользуйтесь как обычно:

```powershell
python -X utf8 -m eightfm eval-rl --model models/lu_luna_absolute.json --games 100 --seed-base 90000
python -X utf8 -m eightfm play-game --model models/lu_luna_absolute.json
```

Если хотите сделать её основной «Луной» — переименуйте в `models/lu_luna.json`.

> **Совместимость.** «Абсолютная» модель использует расклад признаков `v2`
> (158 / 32), старая `lu_luna` — `v1` (115 / 25). Они не взаимозаменяемы как
> чекпоинты: продолжайте `absolute` только из `absolute`. При этом обе модели
> спокойно сосуществуют — сеть помнит свою версию признаков и грузится как есть,
> а в одной игре они могут играть друг против друга.

## Сколько это займёт

Замеры на 4-ядерной машине с сетью `absolute` (512/256/256) и раскладом `v2`:

| Операция | Время |
|---|---|
| Сбор 48 игр в 4 процесса | ~7 с (≈140 мс/игру) |
| PPO-апдейт (батч 1024, 8 эпох) | ~0,3 с |
| Полная оценка (60 игр × 4 противника × 5 форматов + 40 личных встреч) | ~2 мин (последовательно) |

Сбор игр — почти всё время, поэтому `--workers` важнее размера сети. Оценка
идёт на одном ядре и стоит около 2 минут, но запускается раз в 50 апдейтов
(`--eval-every`), так что в среднем это ~2–3 с на апдейт. Итого ориентир:
**6000 апдейтов ≈ 11–13 часов**, то есть примерно одна сессия Kaggle или две
с учётом лимита `--time-budget-seconds`. Хотите быстрее — уменьшите
`--total-updates`; хотите сильнее — увеличивайте.

## Восстановление после обрыва

Драйвер специально пишет `latest`-чекпоинт каждые несколько апдейтов. Даже
если процесс убьют жёстко, следующий запуск:
1. прочитает `driver_state.json` (или, если его нет, начнёт с шага 0);
2. загрузит `lu_luna_absolute-latest.json`;
3. продолжит с сохранённым learning rate и энтропией.

Расписание `learning rate`/`энтропии` вычисляется от **глобального** шага,
поэтому при возобновлении оно не «перезапускается», а плавно продолжается.
